# MoonBit 项目调研指南

本指南用于在参赛选题、项目申报或项目重复性判断前，调研 MoonBit 当前已有包及其实现情况。调研的目标不是只列出搜索结果，而是帮助判断：应该新建项目、扩展已有项目，还是参与已有项目维护。

## 固定搜索流程

### 1. 使用 `moon search` 搜索关键词

不要尝试通过 `https://mooncakes.io/search?q=<keyword>` 搜索。该网站搜索页不提供可依赖的 HTTPS 查询入口。使用本地 Moon 工具链执行：

```bash
moon search <keyword> --limit <number>
```

例如：

```bash
moon search agent --limit 5
```

> 详细用法可以通过 `moon search --help` 查看。
> 如果用户没有安装 MoonBit 工具链，推荐他先前往 [MoonBit Install](https://www.moonbitlang.com/download) 安装 MoonBit 工具链。

搜索结果通常包含模块名、版本和简介。必要时分别搜索多个关键词，不要只凭一次搜索得出“生态中不存在相关项目”的结论。

记录每次搜索使用的关键词、命令、结果和调研日期。搜索结果是动态信息，报告中应标明查询时间。

### 2. 使用 `mooncakes.io/docs` 查看包详情

从搜索结果得到模块名后，对需要深入了解的包访问：

```text
https://mooncakes.io/docs/<包名>
```

例如模块 `moonbit-community/miniio` 对应：

```text
https://mooncakes.io/docs/moonbit-community/miniio
```

使用网页抓取工具读取详情页。详情页是调研 MoonBit 包的主要资料来源，重点提取包的功能定位和 README、版本、作者、许可证和仓库链接、最近更新时间和下载量、标签和安装命令、公开 API、示例、测试说明、支持的后端或运行环境，以及页面提供的源文件列表和源码链接。

### 3. 必要时查看源码仓库

详情页中的 README、API 文档和元数据不足以判断实现完成度时，再读取其 Repository 链接对应的公开仓库。重点检查 `moon.mod`、`moon.pkg`、源码目录、测试文件、示例、CI workflow、提交历史、最近维护情况、未完成标记、`LICENSE*` 以及第三方来源说明。

不能访问仓库、不能运行代码或无法确认某项信息时，明确写成“未核实”，不要推断为“不存在”或“未实现”。

## 包信息记录表

| 维度 | 记录内容 |
| --- | --- |
| 模块 | 完整 MoonBit 模块名 |
| 版本 | 搜索结果或详情页显示的版本 |
| 定位 | 解决的问题、目标用户和适用场景 |
| 功能 | 已公开的主要 API 和能力范围 |
| 发布 | 是否能在 `mooncakes.io` 找到详情页 |
| 工程 | 源码、测试、示例、CI 和项目结构情况 |
| 维护 | 最近更新时间、提交活动和维护信号 |
| 许可证 | 包许可证及已发现的来源说明 |
| 来源 | 详情页、仓库和其他参考链接 |

更新时间和下载量只作为维护度或使用度的参考信号，不单独作为项目成熟度结论。详情页缺失也不等于没有源码项目，必要时继续查找公开仓库；反过来，存在源码仓库也不等于已经发布到 `mooncakes.io`。

## 重合度判断

将拟议项目与已有项目按功能、目标用户、核心 API、运行环境和交付范围比较：

- **高度重复**：目标和核心功能基本一致，且已有项目实现完整、文档和测试可用并处于维护状态。优先参与已有项目，不建议直接新建。
- **部分重合**：已有项目覆盖部分能力，但存在明确缺口，例如协议版本、后端、性能、错误处理、工具链集成或文档体验。优先考虑贡献已有项目；独立建设时必须写清边界和新增价值。
- **生态空白或早期实现**：没有发现功能相近项目，或已有项目仍是空壳、实验性实现。可以考虑新建，但仍需评估上游项目、许可证、实现规模和比赛周期。

结论必须同时说明“已有项目覆盖什么”和“拟议项目新增什么”。不能仅凭包名相似、同一作者或一次搜索结果认定重复。
